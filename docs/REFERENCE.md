# 详细说明

这里是原来的长说明，给开发和打包时查阅。软件介绍以仓库首页的 `README.md` 为准。

面向 Windows 10/11 x64 的本地 PHP 开发环境管理器。使用 Go、Wails v3、Vue 3、TypeScript、Naive UI 和 SQLite。

## 使用

解压发行包并运行 `PHPTools.exe`。首次启动选择一个独立空目录，例如 `D:\PHPTools`。组件按需在线下载，不随软件打包。运行环境要求 Microsoft Edge WebView2 Runtime。

首次使用步骤见发行包内 `FIRST_RUN.md`。启动前使用桌面框架相同的检测器检查 WebView2，缺失时通过 Windows 原生对话框打开微软安装页面并支持安装后重试。“检测”新增运行依赖检查；“设置 → 检查运行依赖”可进入，按组件实际导入信息关联 VC++ 运行库。官方安装入口只接受内置依赖编号，安装完成后由用户重新检测，无后台自动安装或持续扫描。

检测只读取组件元信息、系统运行库文件和版本，不执行组件二进制、不修改系统运行库。未关联组件的缺失运行库标记为按需安装；x86 或其他年代的运行库不能替代所需 x64 版本。干净 Windows 的完整验收仍待进行，步骤及当前验证范围见 `FIRST_RUN.md`。

1. 在组件中心安装需要的 Nginx、PHP、MySQL、Redis 版本。
2. 在实例页创建实例。PHP 版本可同时运行；MySQL 每个实例有自己的端口、数据目录与密码；Nginx 同时只运行一个实例。
3. 启动服务，在站点页填写域名、项目目录、入口目录、端口和 PHP 实例。静态站点不选择 PHP。
   在“数据库管理”页选择已启动的 MySQL 实例，可创建/删除数据库、导入/导出 SQL、创建账号、修改账号密码和管理数据库权限。
4. hosts 更新需要管理员权限时，仅提升固定的域名更新操作。其他 hosts 条目保留，原文件备份在运行环境的 `backups`。
5. 关窗后软件留在托盘；使用“停止服务并退出”结束。数据库关闭失败会保留管理器供查看日志、重试，不自动强杀。

默认建议端口：Nginx 8081、PHP 9100、MySQL 3307、Redis 6380。多个同类实例要指定不同端口；服务仅监听本机。PHP 站点的 PHP 实例需启动，启动 Nginx 时会自动启动已启用站点引用的 PHP。

关闭窗口进入托盘后，界面停止状态和日志自动刷新，并请求 WebView2 挂起；后台服务与任务继续运行。重新打开窗口时恢复界面并立即刷新状态，页面及未保存输入保留。挂起属于 WebView2 的尽力回收机制，节省的内存取决于页面与系统状态。

“设置 → 开机启动”提供开关，切换后自动保存当前用户的 Windows 登录启动项，并保留当前配置目录。仅自动打开 PHPTools，服务仍需手动启动。界面读取 Windows 中的状态；如果系统另行禁用该启动项，会提示到 Windows“启动应用”中处理。移动程序或更换版本目录前，请先在原版本关闭开机启动，再在新位置重新开启，避免启动项仍指向旧程序。

“检测”页提供检测并自动修复功能。应用启动和服务操作失败后自动进行轻量检查，核实进程身份、组件和配置文件、运行目录以及站点设置；确认安全后保存实际进程状态，重建缺失的实例日志目录和 Nginx 临时目录。手动检测额外执行配置校验、监听端口和运行服务响应检查，并核对 hosts 映射。检测复用后台任务，支持取消；不增加定时扫描，托盘挂起期间也不会持续检查。

检测结果区分通过、已修复和需处理。手动检测发现可安全修复的过期进程状态、缺失日志目录或 Nginx 临时目录时，会在对应行提供“修复”按钮；点击后核实当前状态并处理该项。其他异常提供具体建议，以及站点管理、组件中心、服务实例或日志入口。WebView2、VC++ 运行库异常可点击“修复方法”，通过微软安装程序安装或修复，再重新检测。检查不会自动启停服务、接管归属不明的进程、覆盖现有配置或创建数据库目录；缺失的站点配置需要在站点管理中核对后保存生成。MySQL 响应检查只执行 `SELECT 1`，临时凭据文件沿用现有访问控制并在结束后清理。

与其他程序并用时，HTTP 站点必须使用不同端口。站点的 HTTP 和 HTTPS 监听 `0.0.0.0`，同一网络里的设备可以访问；PHP、MySQL、Redis 以及 Nginx 实例自身仍只监听 `127.0.0.1`。站点开启 HTTPS 且 HTTP 端口不是 443 时，可以强制把 HTTP 访问跳转到 HTTPS；`/.well-known/acme-challenge/` 仍由 HTTP 提供，以便继续申请证书。端口本身已是 443 时没有 HTTP 入口，不能开启这项跳转。PHPTools 在启动、保存站点及重载配置前检查主配置、包含文件和隐式默认监听的全部端口；发现其他进程监听时拒绝操作并报告端口与 PID，不停止对方服务。

## 应用升级

更新地址已写在程序内，设置页不显示、也不能修改。每次显示窗口时检查更新，两次检查至少间隔 30 秒；30 秒内反复显示和缩小只检查一次。缩小到托盘后不会定时扫描。也可在“设置 → 应用升级”点击“检查更新”。发布时把更新清单放在程序使用的固定地址，并把对应的 Windows x64 程序放在同站点的 `PHPTools.exe`；清单里的 `downloadUrl` 必须指向该 EXE。

发现新版本后，侧栏左下角显示“新”，设置页提供“立即升级”。点击后下载本次已检查的版本，核对 SHA-256、大小及 Windows x64 程序格式，再停止受管服务、替换应用并重新打开。重新打开后，会启动升级前正在运行的实例。下载期间可取消，替换失败时尝试恢复旧程序并报告原因；下载、校验或服务停机失败会终止升级。升级前请保存开发工作。更新保留环境目录、数据库和当前配置档案；仅更新 PHPTools 程序，不升级 PHP/MySQL 等组件。

更新清单使用 JSON，字段为 `version`、`downloadUrl`、`sha256`、`size`、`releaseDate`、`notes`，可选 `mandatory` 用于标记重要更新。`version` 采用稳定版本的三段数字，如 `0.1.18`；`downloadUrl` 必须通过 HTTPS 直接下载 Windows x64 的 PHPTools EXE，不能指向 ZIP、网页或其他安装器；`sha256` 和 `size` 必须对应该 EXE。清单与下载过程的重定向也必须保持 HTTPS。检查失败会显示具体错误，不会显示“当前版本无需升级”。

## 站点列表显示与排序

站点管理右上方的“显示列”图标可以隐藏或显示各列，至少保留一列，也可恢复为全部显示。

站点名称与域名分两行显示，域名后显示非 80 端口。列表使用普通表格样式，排序列与其他列底色一致，各列随表格一起横向滚动。列表高度随内容自然展开，长列表通过页面上下滚动。“目录”在资源管理器中打开项目目录，路径不可访问时显示具体错误。站点行提供“访问”“编辑”“目录”“删除”操作；查看站点日志请从左侧“日志”页面选择本地站点。拖动表头右侧的分隔线可调整列宽。

点击“站点 / 域名”“添加日期”“最近活动日期”表头，在升序、降序、默认顺序之间循环切换，一次按一列排序。默认按站点配置最近成功保存的时间倒序，也可点击“恢复最近修改优先”返回默认。修改时间持久保存，刷新和读取访问日志不会改变它；旧版没有修改时间的站点使用已记录的添加日期，两者均未记录时排在后面，直到下次成功保存。显示列和排序设置在重启后保留，调整列表不会重载 Nginx 或更新 hosts。已移除置顶操作，旧版置顶记录不再影响排序。

新建站点记录首次添加到 PHPTools 的时间，编辑不会改变添加日期；旧版未保存该信息的站点显示“未记录”。最近活动日期取站点独立访问日志中最近一条完整 HTTP 请求的时间，按本机时区显示，包含浏览器访问和检测请求；没有可读取的记录时显示“暂无记录”。读取随现有界面刷新进行，日志未变化时复用解析结果，不写入服务配置。

## 侧栏菜单

在“设置 → 界面设置 → 管理菜单”中，使用上下箭头调整左侧菜单顺序，用开关显示或隐藏菜单。“设置”始终显示，方便恢复其他入口。修改点击“保存”后生效，“取消”不保留修改；“恢复默认”先还原弹窗中的顺序和开关，保存后应用。隐藏菜单不停止服务，页面内的快捷入口仍可打开对应功能。

偏好保存在当前配置目录的 `sidebar.json`（默认 `%APPDATA%\PHPTools`），独立于环境数据和安装目录，重启或替换程序后继续保留。配置文件损坏时使用默认菜单，并在概览显示提示。增加新菜单后，已保存的菜单会补上新入口，原有顺序和自定义名称保留。

## 公网证书

“证书”菜单可以为站点的第一域名和第二域名申请 Let’s Encrypt 证书。域名必须能从公网解析到这台电脑，并且 80 端口可以从公网访问。本地域名、`.test` 等保留域名不能申请。

申请时会在站点配置中提供 `/.well-known/acme-challenge/` 验证地址。站点本身不监听 80 时，会临时增加一个只用于验证的 80 端口，完成后移除。验证通过后安装公网证书、开启 HTTPS 并重载 Nginx。也可以在添加窗口里贴上已有的公钥和未加密私钥。公钥必须包含站点域名，并由系统信任的机构颁发；中间证书可以和站点证书贴在一起。之后保存站点不会用本地证书覆盖仍有效的公网证书。证书不包含当前域名或 30 天内到期时，需要在证书菜单重新添加或重新申请，或改回本地证书。

通知邮箱保存在当前环境的 `certs` 目录，只用于证书机构的到期通知。账户私钥也保存在该目录，不要删除正在使用的 `acme-account.key`。

## 内存占用

概览中的“软件内存”显示 PHPTools 主程序及其 WebView2 界面进程的 Windows 工作集合计，不包含 PHP、MySQL、Nginx、Redis 或外部数据库客户端。鼠标移到说明图标可查看主程序、界面进程及专用提交内存。工作集包含共享页面，多进程相加可能重复计入共享页，与任务管理器默认的专用工作集列口径不同；读取不完整时会明确标记。

采样复用界面状态刷新，最短间隔 5 秒，不添加独立后台计时器。窗口进入托盘后随界面停止刷新。Windows 自动管理工作集，本版不提供强制清内存操作；正常安装、失败或取消后会自动删除下载临时文件，暂不增加常规缓存清理按钮。

## 入口目录与伪静态

站点入口目录通过“浏览”选择，只能选择项目目录本身或其子目录，并保存为相对路径。`.` 表示项目根目录，也可一键重置；修改项目目录后需要重新选择入口。链接到项目外部的目录不可作为入口。

伪静态下拉提供 Laravel、ThinkPHP 5.0/5.1、ThinkPHP 6/8、WordPress 单站、Yii2、Symfony 美化 URL、CodeIgniter 4 和 Typecho。选择后填入可编辑规则，不会替换项目入口目录或 PHP 实例；修改规则后显示为自定义。选择“默认规则”恢复当前站点模式的默认规则。

这些预设用于独立域名下的根路径部署，不适用于 `/blog/` 等 URL 子路径。Laravel、ThinkPHP、Symfony、CodeIgniter 通常选择 `public`；Yii2 Basic 选择 `web`，Advanced 前后台分别选择 `frontend/web`、`backend/web` 并创建独立站点。WordPress 和 Typecho 选择各自安装目录。具体 PHP 版本与应用自身的固定链接、路由设置仍需满足项目要求；预设提供路由及所列目录保护，不代表完整的生产服务器加固配置。

每个预设的官方参考链接保存在 `internal/sites/presets.go`。`cmd/rewritecheck` 在独立环境使用真实 Nginx 与 PHP 的轻量入口文件验证配置、路由、参数、POST、静态文件及缺失 PHP 文件，不替代完整框架的安装测试，不修改系统 hosts。

## 数据与配置

环境目录下分别保存 `packages`、`instances`、`sites`、`conf`、`cache`、`logs`、`backups` 和 `metadata.db`。`sites` 只放项目目录，Nginx 站点配置放在 `conf`。首次创建环境后，可以选择在桌面创建指向 `sites` 的「网站根目录」快捷方式。站点操作里的「目录」打开该站点的项目目录。打开已有环境时，会把原来放在 `sites` 里、由 PHPTools 生成的配置移到 `conf`，并改写 Nginx 的引用。PHPTools 使用自己的组件和进程，不把环境目录放进其他软件的安装目录。

MySQL 密码由当前 Windows 用户的凭据管理器保存，元数据库不保存明文密码。移除实例只移除活动记录，保留实例目录、数据、凭据及 `retained-instance` 元数据。组件被活动实例引用时禁止卸载。MySQL 数据目录不能直接跨版本共用；首版不提供数据库升级、降级或旧环境迁移。

## 数据库管理

系统数据库（`information_schema`、`mysql`、`performance_schema`、`sys`）默认隐藏，可通过“显示系统数据库”临时查看，原有只读保护保留。

业务数据库行提供“管理”按钮，点击后检测 Navicat、DBeaver、HeidiSQL、MySQL Workbench、SQLyog、DataGrip 和 phpMyAdmin。检测范围为 Windows 已安装程序注册信息、PATH、常见安装目录和 PHPTools 已配置站点，不进行全盘扫描。便携版可通过浏览手动添加 `.exe`；phpMyAdmin 可添加完整 HTTP/HTTPS 地址，记录保存在当前环境的元数据库中。

工具面板显示并可复制当前实例的主机、端口、用户名和数据库名。客户端启动后按这些信息连接并输入实例密码；现有 phpMyAdmin 可能默认连接其他 MySQL，请核对服务器和端口。仅找到 phpMyAdmin 文件目录时会显示“待配置”，需要补充可用访问地址。此功能打开已有工具，不会安装 phpMyAdmin，也不会修改已有工具的连接配置。

“数据库管理”页只连接 PHPTools 创建的 MySQL 实例，使用该实例保存的管理凭据。新数据库使用 `utf8mb4` 与 `utf8mb4_unicode_ci`，新建库名支持 1–64 位字母、数字和下划线。删除数据库需要输入库名确认，系统数据库仅供查看。通过 SQL 导入产生的其他合法库名可继续查看、导入、删除与管理权限；受 Windows MySQL 客户端的参数编码限制，非 ASCII 库名暂不支持内置导出，需使用支持 Unicode 的外部数据库客户端。

导入接受 UTF-8 编码的 `.sql` 文件，支持 `DELIMITER`、存储过程等 MySQL 脚本。导入以所选库作为默认数据库；脚本中的 `USE`、DDL 等语句会按脚本实际执行，务必核对文件。失败或取消可能已经写入部分数据，不会自动回滚整份文件。导入、导出通过后台任务执行，可查看结果及取消。导出包含表结构、数据、触发器、存储过程和事件，完整写出后才发布为目标文件，且不覆盖已有文件。`--single-transaction` 为 InnoDB 提供一致性快照；导出期间请避免 DDL，非事务表需要自行暂停写入。

账号支持创建、修改密码、删除、查看现有授权，以及按数据库授予或撤销所选权限。用户名支持 1–32 位字母、数字、下划线、点和短横线，密码至少 8 个字符；主机字段对应 MySQL 的 `user@host`。不开放全局权限和授权转授，`root`、`mysql.*` 与匿名账号受保护，仅可查看。撤销数据库级权限不会删除表级或其他来源的授权，请同时核对授权明细。

配置保存会创建备份。Nginx 校验通过后重载，其他组件需要重启。受管的进程标识、数据目录、监听地址等关键配置受约束，不能通过文本编辑将其指向其他环境。

进程记录缺失或损坏时，只有确认旧进程已退出或 PID 已被其他身份复用，才会清理过期状态并允许重新启动；仍在运行且缺少归属记录的进程不会被接管或停止。

配置目录默认位于 `%APPDATA%\PHPTools`。需要独立配置档案时运行：

```powershell
.\PHPTools.exe --config-dir D:\MyPHPToolsProfile
```

同一用户只运行一个管理器实例。环境目录初始化后固定，首版不支持在设置页移动它。

## 下载来源与校验

- PHP：官方 Windows JSON 提供当前分支的 SHA-256。PHP 5.6.40、7.0.33、7.1.33、7.2.34、7.3.33 的 x64 NTS 包于 2026-10-19 从官方 HTTPS 归档下载，检查 ZIP 内容、PE 架构与版本后固定首版 SHA-256。这些摘要由 PHPTools 核验生成，界面不会标成 PHP 官方发布摘要。
- Nginx：官方 Windows ZIP，校验发布者 PGP 签名与完整指纹。官方 Windows 包的实际架构在安装后识别，可能为 x86，可运行在 x64 Windows。
- MySQL：官方 Windows ZIP 与 PGP 签名。在线刷新只接受确实存在 Windows ZIP 和签名的 5.7、8.0、8.4 版本。
- Redis：第三方 `redis-windows/redis-windows` 的 Cygwin 非 Service ZIP，校验发布资产 SHA-256，保留随包运行库。不是 Redis Ltd 自行发布的原生 Windows 包。

下载中断、校验失败或解压失败会清理临时内容，完整包校验后原子发布。下载安装完毕但元数据库写入前中断，可通过再次安装同一版本恢复登记。版本目录刷新失败会显示具体错误并保留已有可用目录。

老 PHP 需要对应 Microsoft Visual C++ 运行库（例如 PHP 5.6 的 VC11）。缺少系统运行库时会显示启动错误，需要安装对应微软运行库。PHPTools 使用组件自带或系统已安装的运行库。

PHP 5.6/7.0 的 Windows 版本存在 UTF-8 路径限制，环境目录、项目目录及 PHP 文件名请使用英文（可以有空格）。软件会在创建旧 PHP 实例、保存站点时检查目录并给出提示。PHP 8.0 的中文及空格项目路径已真实验证。[PHP 7.1 的 UTF-8 路径支持说明](https://www.php.net/manual/en/migration71.windows-support.php#migration71.windows-support.long-and-utf8-path)。

## 开发与打包

需要 Go 启动器、Node.js 24 与 npm、WebView2。项目固定 Go 1.26.9；Go 会按项目工具链设置下载对应版本，不更改系统 Go 安装。

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1
```

脚本从 `internal/desktop/app.go` 的 `appVersion` 读取发行版本，并核对前端 `package.json` 与锁文件中的版本。它固定 Wails CLI 和模块版本，生成 TypeScript 绑定，运行前后端检查，输出 `dist\PHPTools-0.1.18\PHPTools.exe` 与 ZIP 发行包。

发布在线升级时，为构建脚本增加 `-UpdateDownloadURL` 参数，值为准备发布的真实 HTTPS EXE 下载地址；可用 `-UpdateNotes` 提供更新说明。脚本另外生成 `dist\PHPTools-0.1.18-update.json`，摘要和大小自动取自本次 EXE。默认不生成带占位地址的清单。构建脚本不会上传文件；发布者需将 EXE 与 JSON 上传到自己的 HTTPS 服务，并把 JSON 的访问地址提供给用户。发布后应核对远端 EXE 与清单中的摘要一致。

```powershell
go test ./...
go vet ./...
go run ./cmd/smoke -help
go run ./cmd/database-smoke -help
```

`cmd/smoke` 是独立真实验收工具，会下载组件并创建测试实例；请先查看帮助。普通单元测试不下载组件、不更新系统 hosts、不启动现有服务。

所有命令行验收工具默认在系统临时目录下创建本次独占环境；可用 `-root` 指定一个尚不存在的绝对路径，已有目录会被拒绝。测试成功或失败后，先停止测试服务、清除临时凭据并关闭数据库，再删除本次环境；仍有测试进程或目录归属发生变化时拒绝删除并报告错误。JSON 验收报告保存在项目 `build/qa`，不会为保存报告保留运行环境。

`cmd/database-smoke` 复用已安装的 PHPTools 官方 MySQL 包进行数据库管理验收，不下载组件。必须指定包含 `.phptools-package.json` 的受管安装目录 `-mysql-package` 和准确的 `-version`。会复制安装包并创建测试实例，验证 SQL 往返恢复、账号认证和权限、失败及取消行为；可用 `-report` 指定环境目录之外的报告位置。

`cmd/health-smoke` 和 `cmd/port-smoke` 必须显式传入只读 Nginx 包目录 `-source`；`cmd/rewritecheck` 必须显式传入已安装 PHP 8.0 与 Nginx 的只读环境目录 `-source-root`，不再依赖以前保留的测试环境。

Wails v3 当前固定预发行版本，升级时需要重新验收窗口、托盘、绑定与服务生命周期。首版不包含旧环境迁移、Composer 或 Apache。站点可以生成本地 HTTPS 证书：证书由当前环境自己的颁发机构签名，Nginx 在 443 端口使用，首次开启时由 Windows 询问是否信任该机构。
